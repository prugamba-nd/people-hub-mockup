PEOPLE HUB MOCKUP

Open site/index.html to review the hub. The five sidebar categories, thirteen
subcategories, and twelve profile links open static pages (31 pages total).
No dependencies or backend are needed. Groups without sample people display
"Profiles coming soon." Some sample people belong to more than one group.

The markup follows the existing NDT4 header, page, section navigation, and
People Card components. The official NDT4 stylesheet loads from:
https://conductor.nd.edu/stylesheets/themes/ndt/4.0/ndt.css

assets/site.css holds small mockup-specific additions. assets/fallback.css
loads only if the official stylesheet fails, allowing an offline preview.
The fallback is an approximation and is not the official NDT4 stylesheet.

People and roles are fictional. All profile images use a neutral placeholder.
The wide photo is reused from the existing saved People mockup in this
workspace (mockups/people.html); it depicts scholars, not the sample profiles.
Notre Dame marks are reused from exemplar/assets, originally obtained from
webtheme.nd.edu. The site requests no indexing.

The compact fixed navigation follows www.nd.edu: the main header scrolls
away, then NDT4's header-nav-fixed component appears. assets/ndt.js is the
official NDT4 runtime copied from conductor.nd.edu/javascripts/themes/ndt/4.0/ndt.js.
assets/shield.svg is the gold shield from www.nd.edu/assets/images/icons/ndt4-v1.svg.
The fixed navigation and menu dialog use NDT4 styling and behavior.
The sidebar uses NDT4's three-level section navigation, including current-page
highlighting. The same hierarchy is available under Browse people in the menu.
The People hub uses NDT4's Container Page Header with breadcrumbs, title, and
the wide image in one hero. The sidebar and introductory copy begin below it,
following the structure used on www.nd.edu/about/.

Local dev server (opens the browser): python3 dev.py
Dev URL: http://127.0.0.1:4173/
Stop the dev server with Ctrl+C. Local file edits appear after refreshing.
Rebuild: python3 build.py
Publish: sh publish.sh
Optional: sh publish.sh OWNER/DIFFERENT-REPOSITORY-NAME

Publishing requires network access to GitHub and an authenticated GitHub CLI
account able to create a public repository and enable GitHub Pages.
If needed, authenticate in your terminal using gh auth login first.
The publishing script resumes an existing matching repository or creates a
new public repository. It publishes only site/ to the gh-pages branch, then
configures GitHub's built-in branch publication. It does not require the
OAuth workflow scope. No branches are force-pushed and no global Git settings
are changed. Rerun the script after changing the source to publish an update.
The script explicitly requests a Pages build, waits for its result, and
checks that the public URL serves the People hub before reporting success.
The Pages setup follows GitHub's documentation:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site

The terminal run created the public repository and uploaded the source. Its
workflow push was rejected for missing OAuth workflow scope. The connected
GitHub app then prepared gh-pages with the complete site and local publishing
was changed to branch publication. The shell still cannot resolve
api.github.com; the connector has no Pages administration capability.
The final Pages setting must be made from a terminal with GitHub access.
